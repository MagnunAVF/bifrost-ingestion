# Bifröst: catalog ingestion and semantic deduplication (Go, Python agent)

## Current focus

Milestone M2 (v0.2.0): intelligent decision engine (Go MCP server, Python agent, hybrid triage).
Plan: docs/milestones/M2.md. Roadmap: docs/plans/ROADMAP.md.
Target machine: Apple M1, 8 GB RAM, Ollama running locally. Keep memory small: stream input,
float32 vectors, no full-file reads of the payload.

## Commands

- Dry run on the fixtures: `make run` (writes nothing; uses tmp/catalog.work.db)
- Real run on the working copy: `make run WRITE=1`; fresh copy: `make reset-db`
- One package's tests: `go test ./internal/vector -run TestNearest -v`
- After editing SQL in internal/catalog/queries or migrations: `make generate`
- Fuzz the sanitizer: `make fuzz`; benchmarks: `make bench`
- End-to-end with real Ollama: `make e2e` (needs Ollama running and the model pulled)
- Python agent (run inside agent/; `uv run` uses the locked env):
  `uv run pytest -k <name> -v`, `uv run ruff check --fix . && uv run ruff format .`,
  `uv run mypy .`. Plan 2.0 adds these to `make check`; until then agent/ doesn't exist.
- Before saying a task is done: `make check` must pass (it never needs Ollama or an LLM)

## Architecture (package boundaries enforced by depguard)

- cmd/bifrost → CLI flags and wiring only (`migrate`, `ingest`; `mcp` from plan 2.1).
- internal/ingest → stream-decode ProductEntry.json, sanitize, build identity strings. No DB, no HTTP.
- internal/embed → Embedder interface, Ollama client (net/http only), Fake. No DB.
- internal/vector → normalize, cosine, in-memory Index. Standard library only.
- internal/catalog → the ONLY package that touches SQLite: Open, Migrate, WithTx, sqlc queries.
- internal/dedup → cold start, decision matrix, upsert, run report.
- internal/mcp (plan 2.1) → MCP server over stdio: tool schemas and handlers that call catalog
  store methods and vector. No database/sql.
- internal/catalog/db is generated by sqlc. Never edit it.
- agent/ (plan 2.0+) → Python LangChain agent, its own uv project. Talks to Go only through
  `bifrost mcp` over stdio and never opens catalog.db. Calls Ollama for its chat model.

## Conventions

- Errors: wrap with fmt.Errorf("doing x: %w", err); sentinel errors in internal/platform/errs.
- context.Context is the first parameter of every function that does I/O.
- Dependencies come in through constructors and interfaces. No globals, no init().
- Tests: table-driven, testify require/assert. Unit tests never call real Ollama (use embed.Fake);
  real calls only in files with `//go:build integration`.
- Vectors are []float32, normalized once when added to the index.
- Logging: log/slog. Every run ends with a report: inserted, linked, rejected, suspicious.

### Python (agent/)

- Python 3.13 (agent/.python-version), managed by uv; uv.lock is committed. Never pip install.
- Type hints everywhere; `mypy --strict` and ruff (lint and format) must be clean.
- Same shape as the Go code: dependencies through constructors and parameters, no work at import
  time, no module-level mutable state. Async I/O takes a timeout.
- LLM output is parsed into a pydantic model; invalid output is an error, never a guess.
- Errors: raise specific exception types and chain the cause (`raise X(...) from err`); never
  a bare `except:`.
- Logging: stdlib logging to stderr.
- Tests: pytest, parametrized like the Go tables. Unit tests never call Ollama, an LLM or a real
  `bifrost mcp` (use a fake chat model and a fake MCP session); real calls only in tests marked
  `@pytest.mark.integration`, which `make check` skips.

## Data rules

- testdata/catalog.db and testdata/ProductEntry.json are read-only fixtures. Tests copy them
  into t.TempDir(); `make run` uses tmp/catalog.work.db.
- Use the real schema and field names from docs/data-notes.md. Never guess them.
- All SQL goes through sqlc with parameters. Never build SQL with fmt.Sprintf or concatenation.
- Python never touches SQLite. Agent tests use recorded MCP tool results, not the fixtures.

## Issues, branches and pull requests

- Issues are referenced ONLY as ENG-<n>, the id at the start of the GitHub issue title
  ("ENG-3: [1.2] ..."). It is NOT the GitHub issue number (ENG-3 is issue 2). GitHub titles are
  the source of truth: before any `gh issue ...` call, resolve with `scripts/eng-issue.sh ENG-<n>`
  (prints the number; `scripts/eng-issue.sh <number>` prints the ENG id). Never write "#<n>" for
  an issue and never "ENG-#<n>". Pull requests are referenced as "PR #<n>".
- Branches: feat/ENG-<n>-<slug>, fix/ENG-<n>-<slug>, chore/ENG-<n>-<slug>, docs/ENG-<n>-<slug>,
  always created from origin/dev.
- PR titles: conventional commits ending in "(ENG-<n>)",
  e.g. "feat(ingest): stream-decode product entries (ENG-3)". Commits add the task (see Commits).
- Every PR targets dev. Only release PRs (dev → main) and hotfix/\* target main.
- Don't use closing keywords ("Closes ..."); the close-issue workflow closes ENG-<n> on merge.
- Never push to dev or main directly. Never force-push.

## Rules

- Never modify an existing test to make it pass. If a test seems wrong, stop and ask me.
- No new dependencies (`go get`, `uv add`) without asking.
- Keep changes scoped to the issue.

### Test-Driven Development (mandatory)

Always follow TDD: write or identify the tests first, confirm they fail, then write the minimum code to make them pass, then refactor with the tests green.

- Before writing any implementation code, check whether tests already exist for the feature or module you are changing.
- If tests DO NOT exist: stop and propose a list of test cases covering both the happy path and the error paths (invalid input, edge cases, failures of dependencies). Wait for my approval before writing the tests or any implementation.
- If tests DO exist: use them as the specification. NEVER modify, delete, skip, or weaken existing tests to make code pass. If you believe an existing test is wrong or outdated, stop and explain why instead of changing it.
- Run the test suite after each change and report the results.

### Commits (mandatory)

- Create one commit per task within an issue. Never bundle multiple tasks into a single commit, and never make one commit for a whole issue.
- Commit as soon as a task is complete and its tests pass, before starting the next task.
- Reference the issue and task in the message, ONLY as ENG-<n> (never "#<n>" or "ENG-#<n>"),
  e.g. `feat(auth): add token validation (ENG-12, task 2/4)`.
- Do not squash, amend, or rewrite previous commits unless I ask.

## Gotchas

- SQLite can't change a column's type with ALTER TABLE: rebuild the table (internal/catalog/CLAUDE.md).
- The modernc driver name is "sqlite", not "sqlite3".
- Ollama's first request loads the model and is slow; use a generous timeout for it.
- Don't os.ReadFile + json.Unmarshal the payload; stream it with json.Decoder.
- MCP over stdio owns stdout: in `bifrost mcp` (and anything the agent spawns) log to stderr only,
  or the session breaks.
- 8 GB RAM holds the embedding model and a small chat model at once only barely; don't load a
  second chat model, and keep the agent's context short.
