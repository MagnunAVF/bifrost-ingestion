# M1: Foundation and local MVP (v0.1.0)

## Goal

Deduplicate ProductEntry.json against catalog.db semantically, on an Apple M1 with 8 GB RAM.

## Exit criteria

- [ ] `bifrost migrate` fixes SellerProduct.SellerProductId to accept UUIDs without losing rows
- [ ] `bifrost ingest` processes the fixture end to end; malicious and malformed entries are
      handled (stored as data or rejected with a reason) and listed in the report
- [ ] Duplicates are linked, novel products inserted + linked; re-running creates nothing new
- [ ] Threshold calibrated on the real data, with evidence in Decisions and ADR
- [ ] `make check` green in CI; `make e2e` green locally with Ollama
- [ ] docs/architecture.md and the ADRs reviewed and merged

## Risks

- Ollama cold start and throughput on the M1 make the catalog cold start slow → batch requests;
  measure early in ENG-4.
- Threshold quality decides the whole outcome → calibrate on real data in ENG-6, keep --dry-run.
- sqlc may not parse the table-rebuild migration → fall back to schema.sql (make schema).
- Fixture corruption → deny rules, stop hook, tests on copies.

## Open questions

Pending answers; details and evidence in docs/data-notes.md ("Open questions"):

1. Malformed Ids (entries 92, 180, 268): reject with a reason, or store the raw string?
2. Id validation: 8-4-4-4-12 hex shape only, or full RFC 4122? Normalize case?
3. Uniqueness / idempotency key: SellerProductId unique per seller or globally?
4. Same seller and product with different Ids: one link per Id, or collapse and report?
5. Same Id with a differing Name (55 vs 76): first wins, last wins, or conflict?
6. Exact-match fast path without Ollama: allowed?
7. Threshold calibration set: may we add labelled synthetic pairs in testdata/calibration?
8. The SQLi record: insert as a novel Product with the payload as data, or reject?
9. Attribute drift on a match (Photo/Photography, Levi's/Levis): link only and report?
10. Foreign keys: `PRAGMA foreign_keys = ON` per connection, 12-step rebuild in the migration?
11. Column strictness: TEXT NOT NULL only, or STRICT / CHECK on SellerProductId?

## Decisions

- 2026-10-03: ENG-<n> is the id in the GitHub issue title, not the issue number (they differ for
  ENG-2..ENG-7). GitHub titles are the source of truth; scripts/eng-issue.sh resolves both ways and
  the skills and the close-issue / pr-conventions workflows use it. (ENG-1)
- 2026-10-03: Identity string drops the `| brand: …` / `| category: …` segment when the field is
  missing, null or blank; no empty label and no "unknown" placeholder. (ENG-1)
- 2026-10-03: Go 1.27.1 pinned in go.mod (CI reads it via go-version-file); sqlc, goose and
  govulncheck are `tool` directives; testify for tests. (ENG-1)
- 2026-10-03: `make generate` / `make sqlc-diff` skip while internal/catalog/queries has no .sql
  files, so CI is green before ENG-2 adds the first query. (ENG-1)
- 2026-10-03: SellerProduct is rebuilt with `SellerProductId TEXT NOT NULL CHECK (length 1..64)`,
  not STRICT, plus a UNIQUE index on (SellerName, SellerProductId): ids are unique per seller
  (open questions 3 and 11). UUID format validation stays in ingest. ADR 0001. (ENG-2)
- 2026-10-03: Foreign keys ON and busy_timeout=5000 on every connection; one-connection pool;
  the rebuild aborts before COMMIT on any foreign_key_check row (open question 10). (ENG-2)
- 2026-10-03: `catalog.Open` refuses a missing file (`mode=rw`); journal_mode stays `delete`;
  sqlc parses the rebuild migration, so no schema.sql fallback. (ENG-2)
- 2026-10-03: Malformed Ids are rejected (`Id: not a UUID`) and still flagged, so entries 92,
  180 and 268 are rejects and the SQLi record is reported, not stored (open questions 1 and 8). (ENG-3)
- 2026-10-03: Id check is the 8-4-4-4-12 hex shape only, case-insensitive, stored lowercased; not
  RFC 4122 (open question 2). (ENG-3)
- 2026-10-03: Payload capped at 64 MiB with io.LimitReader; duplicate keys in an element reject
  it; over-length fields are truncated to 256 runes and flagged. (ENG-3)
- 2026-10-03: No inch-mark canonicalization: sanitizing never rewrites legitimate characters;
  `golang.org/x/text` is a direct dependency for NFC. (ENG-3)
- 2026-10-03: The Ollama client batches internally (64 texts per POST /api/embed), applies a 2 min
  per-request timeout through the context (covers the cold model load), caps responses at 32 MiB,
  and fails on count or dimension mismatch with `errs.ErrUpstream`. (ENG-4)
- 2026-10-03: No nomic task prefixes (`search_document:` / `clustering:`) in the embedder; the
  ENG-6 calibration decides, since it changes the identity contract. `embed.Fake` (FNV-1a seed,
  splitmix64) is deterministic but not semantic. (ENG-4)
- 2026-10-03: Measured on the M1 with nomic-embed-text (768 dims): cold start ~1.1 s, warm ~88
  texts/s, so the 975-row catalog cold start is ~11 s. Translation pair (entry 57 vs Product 21)
  cosine 0.94 vs 0.55 for an unrelated row. `make e2e` fails, not skips, without Ollama. (ENG-4)
- 2026-10-03: `vector.Index.Nearest` returns `(id, score, ok, err)`: `ok == false` only for an
  empty index, a dimension mismatch or zero/NaN query is an error. Scores are clamped to
  [-1, 1]; ties go to the earliest insert; adding an existing id is `ErrDuplicateID`. (ENG-5)
- 2026-10-03: `internal/vector` keeps its own sentinels and its own one-method `Embedder` (same
  shape as `embed.Embedder`) so depguard's stdlib-only rule holds; IDs are `int64` (Product.Id);
  the Index is not safe for concurrent use (ENG-6 is single-goroutine). (ENG-5)
- 2026-10-03: Exact brute-force float32 scan over one contiguous slab, no ANN. Measured on the
  M1 at 768 dims: 9.0 ms/query at 10k (31 MB), 91 ms/query at 100k (308 MB); the 975-row
  catalog is ~3 MB and under 1 ms/query. No top-k until ENG-6 calibration asks for it. (ENG-5)
- 2026-10-03: Threshold 0.975 with the nomic `clustering: ` prefix, precision first. Duplicate and
  distinct-product scores overlap (min known duplicate 0.951 prefixed, max distinct catalog pair
  0.970, Hockey Skates/Stick), so the two Portuguese translations (57, 64) are inserted, and no
  distinct catalog pair links. Evidence from catalog leave-one-out negatives, not synthetic pairs
  (open question 7). No top-k needed. ADR 0002. (ENG-6)
- 2026-10-03: `make run` on the fixture: 263 linked, 2 inserted, 1 existing, 3 rejected, 1
  suspicious; lowest linked score 0.984; dry-run counts equal the real run's, and a re-run
  creates nothing. (ENG-6)
