# v0.1.0: Foundation and local MVP (M1)

Released 2026-10-03. Milestone: [M1](../milestones/M1.md). Issues ENG-1 to ENG-7.

## Highlights

- `bifrost ingest` deduplicates a seller's ProductEntry.json against catalog.db semantically:
  each entry is embedded locally with Ollama, matched against the catalog in memory, and either
  linked to an existing product or inserted as a new one and linked (ENG-6).
- On the fixture: 269 records, 263 linked, 2 inserted, 1 existing, 3 rejected, 1 suspicious.
  Re-running creates nothing; `--dry-run` reports the same counts without writing.
- Threshold 0.975 (cosine, nomic-embed-text with the `clustering: ` prefix), calibrated on the
  real catalog with precision first; evidence in [ADR 0002](../adr/0002-similarity-threshold.md).
- `bifrost migrate` rebuilds SellerProduct so SellerProductId is `TEXT` and accepts UUIDs,
  without losing rows, with foreign keys enforced and a UNIQUE (SellerName, SellerProductId)
  index (ENG-2, [ADR 0001](../adr/0001-seller-product-id-text.md)).
- Defensive input: streamed JSON with a 64 MiB cap, duplicate-key rejection, Unicode NFC and
  control-character sanitization, length caps, malformed Ids rejected with a reason, SQL-like
  content flagged as suspicious; every case is listed in the run report (ENG-3).
- `--update fill|none|overwrite` decides what a matched entry may change on its product; Name is
  never updated, flagged input is never applied (ENG-6, [ADR 0003](../adr/0003-catalog-product-updates.md)).
- Exit codes 0 / 1 fatal / 2 usage / 3 completed with failed records; failed records roll back
  alone; fatal errors print the partial report and a hint.
- Fits an Apple M1 with 8 GB: pure-Go SQLite, an exact in-memory index (~3 MB for 975 products,
  under 1 ms/query), ~11 s catalog cold start ([ADR 0004](../adr/0004-pure-go-sqlite.md),
  [ADR 0005](../adr/0005-in-memory-exact-index.md), [ADR 0006](../adr/0006-embedding-model.md)).

## How to run

Prerequisites: Go 1.27.1 and [Ollama](https://ollama.com).

```sh
ollama serve                    # or open the Ollama app
ollama pull nomic-embed-text    # 274 MB

make run            # dry run on a copy of the fixtures (tmp/catalog.work.db)
make run WRITE=1    # real run on the working copy
make reset-db       # start again from a fresh copy
```

`make run` never touches `testdata/`. CLI reference, flags and exit codes:
[README](../../README.md). Design: [architecture](../architecture.md).

Verification for this release: `make check` green in CI on 2889b30; `make e2e` (integration
tests and threshold calibration against a real Ollama) green locally on the M1 on 2889b30.

## Known limits

- One global threshold: the two Portuguese translations (entries 57 and 64) score below it and
  are inserted as new products, reported with their nearest match. M2 routes an ambiguous band
  to an LLM agent.
- Model, prefix and threshold are calibrated on this one catalog; another catalog or model
  needs `make e2e` re-run and the ADRs revisited.
- The catalog is snapshotted and fully re-embedded at every cold start (~11 s for 975 rows,
  estimated ~19 min for 100k).
- Exact O(N) scan in RAM, fine up to ~100k products; one goroutine, one embedding call per entry.
- CLI over a local file only: no remote submissions, no backpressure, no metrics.
- No audit table: the run report is the only record of attribute changes, so keep it
  (`make run WRITE=1 > report.txt`).
- The Id check is the UUID hex shape only, not RFC 4122.

Details and the path to M2-M5: [architecture, section 9](../architecture.md#9-known-limits-and-the-path-to-m2-m5).
